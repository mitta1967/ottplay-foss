נגן HTML5/HLS/Shaka המנוהל שומר על הרשאת ניגון בלעדית אחת בזמן התאוששות ממקור שכשל. הוא יכול גם להשתמש בעד שלוש כתובות URL לגיבוי שהוגדרו במפורש לערוץ חי. הוא לעולם אינו מגלה, מנחש או מחליף ערוץ על סמך הכותרת שלו.

## הגדרת תקרת איכות

פתחו **הגדרות ← הגדרות ממשק** והגדירו **גובה וידאו מרבי (HLS/Shaka)** ו/או **קצב סיביות מרבי לשידור (HLS/Shaka)**. שני האילוצים חלים יחד. **אוטומטי** מסיר את האילוץ המתאים. האפשרויות הנתמכות הן 360/480/720/1080/2160 פיקסלים ו־1/2/4/8/16 Mbps. ההגדרות נשמרות מקומית, משתתפות בתהליך הרגיל של שמירת/ביטול הגדרות ונכנסות לתוקף בתחילת הניגון הבאה, לרבות הפעלה מחדש לצורך שחזור.

אלו תקרות, לא הגדרות קידוד מחדש. שידור הזמין רק ב־1080p אינו יכול להפוך ל־720p. אם אף וריאנט מוצהר אינו מתאים, הנגן מציג **No stream meets the quality limits** ומפסיק לנסות שוב את הבקשה. גובה או קצב סיביות לא ידועים אינם מוכיחים שווריאנט HLS עומד באילוצים.

סינון וריאנטים של HLS מתבצע לפני טעינת המקטעים. hls.js הנוכחי מסיר וריאנטים שאינם מתאימים; גרסאות ישנות ללא `removeLevel` יכולות לשמור רק תחילית רציפה ובטוחה, ועשויות לדחות מניפסט שבו יש וריאנטים מתאימים בהמשך. Shaka משתמש במגבלות היישום `maxHeight`/`maxBandwidth`. ההתאמה האוטומטית ממשיכה בין הווריאנטים שנותרו.

הגדרות אלו חלות על מנועי HLS ו־Shaka המנוהלים. HTML5 רגיל, מפענחים מובנים של הפלטפורמה ומנועי TV/STB שנשמרו אינם חושפים את אותם פקדים. מצב אוטומטי עשוי לבחור בניגון מובנה; ההגדרה אינה כופה עליו MSE. הנגן לא יעביר בקשת HLS שכבר הוגבלה לניגון מובנה ללא מגבלות רק כדי לעקוף שגיאת פענוח. אין בכך הבטחה למקודד מחדש מובנה, למדידת ביצועי חומרה אוטומטית או לפלט פיזי של 720p.

## הגדרת גיבויים מפורשים

1. הפעילו את הערוץ החי הרצוי.
2. פתחו **מידע ← שידורי גיבוי**.
3. בחרו משבצת 1, 2 או 3 והזינו כתובת URL מלאה למדיה ב־HTTP/HTTPS.
4. פתחו שוב משבצת מאוכלסת כדי **לערוך** או **למחוק** אותה. הפעילו את הערוץ שוב כדי להשתמש ברשימה המעודכנת.

כל משבצת שייכת למרחב השמות של אחסון הספק הנוכחי ולצמד המדויק `sourceId`/`channelId`. דור הניגון הנוכחי ותצורת המקור תוחמים את תוקף העורך. החלפת מקורות כאשר תיבת דו־שיח פתוחה מונעת ממנה לשמור במקור המחליף. שינוי מקביל לאותה משבצת נדחה במקום להידרס.

כתובת ה־URL הראשונה נשארת המקור הרגיל של הערוץ. מדלגים על משבצות כפולות וריקות. מתקבלים לכל היותר 256 רשומות ערוצים ו־256 KiB של תצורה. כתובות URL עם פרטי הזדהות במידע המשתמש, רווחים, תווי בקרה, לוכסנים הפוכים או יציאה לא תקינה נדחות. אסימוני שאילתה שסופקו בידי הספק עדיין יכולים להיות חלק מכתובת המדיה: הגדרות הגיבוי הן תצורת מקור מקומית, ולא מנגנון לשיתוף פרטי הזדהות או לפרסומם.

הגיבויים מיועדים **לשידור חי בלבד**. בקשות ארכיון ו־VOD לעולם אינן משתמשות בחלופה חיה: ההקלטה, נקודת תחילת הזמן, הזכויות ומשמעות הדילוג בזמן עשויות להיות שונות. על הבעלים לספק נקודות קצה חיות שקולות ומורשות. כותרת ערוץ תואמת אינה הוכחה לשקילות. זהות הערוץ השמורה, המועדפים וקישור ה־EPG נשארים ללא שינוי כאשר נקודת קצה התעבורה שלו משתנה.

## הבטחות השחזור

- לבקשה יש לכל היותר **שני ניסיונות חוזרים מושהים בסך הכול לאותה כתובת URL בעקבות תקלות חולפות**, ולכל היותר מעבר אחד קדימה לכל אחת משלוש משבצות הגיבוי: לכל היותר חמש יצירות מחדש לאחר ההפעלה הראשונה. מכסה זו אינה מתאפסת בעקבות מופע מפענח חדש או מניפסט מוצלח. שחזור הרשת והפענוח המוגבל הקיים בתוך מנוע HLS פועל לפני מדיניות השחזור החיצונית הזו.
- כשלים בניתוח מניפסט/רמת HLS מאפשרים לכל היותר חיבור מחדש אחד לאותה כתובת URL לכל בקשה, הנספר בתוך אותו סך של שני ניסיונות. מפענח חדש או נקודת קצה לגיבוי אינם מאפסים מגבלה זו.
- כשלי רשת ללא סטטוס, HTTP 408/429 ו־5xx יכולים להשתמש במכסת התקלות החולפות. שגיאות HTTP 4xx אחרות יכולות לעבור לחלופה מוגדרת, אך אינן מנסות שוב את אותה כתובת URL. HTTP **401/403 ושגיאות כניסה למקור מסיימים את הבקשה**, בלי לבדוק פרטי הזדהות חלופיים או נקודות קצה לגיבוי.
- כשלי פענוח יכולים להתקדם לגיבוי מפורש. מגבלות איכות בלתי אפשריות מסיימות את הבקשה. אין מחזור שחוזר למקור הראשי.
- ההשהיה היא 500 אלפיות שנייה, 1 שנייה, 1.5 שניות ואז לכל היותר 2 שניות. קריאות חוזרות כפולות מתאחדות.
- השהיה מסירה את הטיימר המתוזמן ושומרת את הניסיון החוזר הממתין; המשך מתזמן אותו מחדש. עצירה, המתנה, החלפת מקור והחלפת ערוץ מבטלות קריאות חוזרות מושהות. בקשה שנכשלה סופית דורשת בחירה מחדש במפורש במקום ניגון אוטומטי של המפענח שהוצא משימוש.
- כשלי טעינה ואירועי שגיאה קריטית של Shaka משתמשים באותו מסלול; מתעלמים משגיאות ביטול. החיבור מחדש ממתין להשלמת הפירוק האסינכרוני של Shaka.
- השחזור פותר מחדש הפניית Stalker אטומה ומכין שוב גישה למקור מוגן. הוא אינו משתמש מחדש בכתובת URL של loopback ב־iOS שפג תוקפה. מיקום VOD/ארכיון נדגם לפני הפירוק; גיבויים חיים מתחילים בקצה השידור החי שלהם.

המדיניות אינה מוסיפה מנגנון ניטור שני לפריימים שנתקעו. השחזור הקיים של קיוסק, אוטומטי/מובנה ו־HLS ממשיך לכסות את מקרי הכשל שהוא עצמו מזהה. שידור שנתקע בשקט בלי שגלאי קיים כלשהו מדווח על שגיאה מחייב אבחון נפרד.

## אימות ותצפיתיות

`window.__ottStreamPolicy.snapshot()` חושף את שם המנוע, המגבלות המבוקשות, היכולת/הזמינות, מספר הניסיונות, אינדקס נקודת הקצה ומצב השחזור. הוא אינו מכיל כתובת שידור או פרטי הזדהות של הספק. אינדקס אפס מציין את המקור הרגיל; אינדקסים מאוחרים יותר מציינים חלופות ייחודיות שאינן ריקות. זהו מצב אבחוני, ולא API יציב לשליטה מרחוק.

הריצו:

<div dir="ltr">

```sh
node tests/test_stream_policy.cjs
node tests/test_port_engine_lifecycle.cjs
node tests/test_settings_parity.cjs
node tests/test_media_backend.cjs
npm run test:localization
npm run typecheck
npm run build:server
node scripts/check-es5.cjs --server-only
```

</div>

הבדיקות בוחנות סינון איכות כאשר סדר הווריאנטים אינו מונוטוני, מטא־נתונים חסרים, עריכה בתחומי מקור, התנגשויות משבצות, שגיאות כפולות, מכסות מוגבלות, כשלי הרשאת HTTP, ביטול בהשהיה/עצירה/מקור, פירוק Shaka ושימור מיקום VOD. חמש תוויות הניגון החדשות מתורגמות בכל 88 חבילות השפה המופצות; בדיקת התאמה אוטומטית אינה סקירה של דובר שפת אם. ניגון על TV/D1 פיזיים ומניפסטים ייחודיים לספק עדיין מחייבים אימות במכשיר.
