[مالکیت رمزگشا](device-media-backend.md)

پخش‌کنندهٔ مدیریت‌شدهٔ HTML5/HLS/Shaka هنگام بازیابی از منبعی که دچار خطا شده است، یک مجوز انحصاری پخش را نگه می‌دارد. همچنین می‌تواند از حداکثر سه URL پشتیبان که صریحاً برای یک کانال زنده تنظیم شده‌اند استفاده کند. هیچ‌گاه کانالی را بر اساس عنوانش پیدا نمی‌کند، حدس نمی‌زند یا جایگزین نمی‌کند.

![روند بازیابی: یک مجوز پخش، تلاش‌های محدود و پشتیبان‌های صریح](diagrams/stream-recovery.svg)

<a id="set-a-quality-ceiling"></a>

## تعیین سقف کیفیت

**تنظیمات ← تنظیمات رابط** را باز کنید و **حداکثر ارتفاع ویدیو (HLS/Shaka)** و/یا **حداکثر نرخ بیت جریان (HLS/Shaka)** را تنظیم کنید. هر دو محدودیت هم‌زمان اعمال می‌شوند. گزینهٔ **خودکار** همان محدودیت را حذف می‌کند. گزینه‌های پشتیبانی‌شده 360/480/720/1080/2160 پیکسل و 1/2/4/8/16 مگابیت‌برثانیه هستند. تنظیمات به‌صورت محلی ذخیره می‌شوند، تابع روند معمول ذخیره/لغو تنظیمات هستند و در شروع بعدی پخش، از جمله شروع مجدد برای بازیابی، اعمال می‌شوند.

این‌ها سقف هستند، نه تنظیمات تبدیل کدک. جریانی که فقط 1080p دارد نمی‌تواند به 720p تبدیل شود. اگر هیچ‌یک از گونه‌های اعلام‌شده مناسب نباشد، پخش‌کننده پیام **No stream meets the quality limits** را نمایش می‌دهد و تلاش مجدد برای آن درخواست را متوقف می‌کند. ارتفاع یا نرخ بیت نامشخص نمی‌تواند اثبات کند که یک گونهٔ HLS با محدودیت‌ها سازگار است.

فیلتر گونه‌های HLS پیش از بارگذاری قطعه‌ها انجام می‌شود. نسخهٔ فعلی hls.js گونه‌های نامناسب را حذف می‌کند؛ نسخه‌های قدیمی‌تر بدون `removeLevel` فقط می‌توانند یک بخش ابتدایی پیوسته و امن را نگه دارند و ممکن است مانیفستی را رد کنند که گونه‌های مناسب در بخش‌های بعدی آن قرار دارند. Shaka از محدودیت‌های برنامهٔ `maxHeight`/`maxBandwidth` استفاده می‌کند. تطبیق خودکار بین گونه‌های باقی‌مانده ادامه می‌یابد.

این تنظیمات برای موتورهای مدیریت‌شدهٔ HLS و Shaka هستند. HTML5 ساده، رمزگشاهای بومی پلتفرم و موتورهای نگه‌داشته‌شدهٔ TV/STB همان کنترل‌ها را ارائه نمی‌کنند. حالت خودکار ممکن است پخش بومی را انتخاب کند؛ این تنظیم استفاده از MSE را به آن تحمیل نمی‌کند. پخش‌کننده صرفاً برای دور زدن خطای رمزگشایی، یک درخواست HLS محدودشده را به پخش بومی بدون محدودیت تبدیل نمی‌کند. این قابلیت به معنی وجود تبدیل‌کنندهٔ بومی کدک، بنچمارک خودکار سخت‌افزار یا ادعای خروجی فیزیکی 720p نیست.

## تنظیم پشتیبان‌های صریح

1. کانال زندهٔ مورد نظر را پخش کنید.
2. **اطلاعات ← جریان‌های پشتیبان** را باز کنید.
3. جایگاه 1، 2 یا 3 را انتخاب و یک URL کامل رسانه با HTTP/HTTPS وارد کنید.
4. جایگاه پُر را دوباره باز کنید تا آن را **ویرایش** یا **حذف** کنید. برای استفاده از فهرست تازه، کانال را دوباره شروع کنید.

هر جایگاه متعلق به فضای نام ذخیره‌سازی ارائه‌دهندهٔ فعلی و دقیقاً زوج `sourceId`/`channelId` است. نسل فعلی پخش و پیکربندی منبع، محدودهٔ اعتبار ویرایشگر را تعیین می‌کنند. اگر هنگام باز بودن پنجرهٔ گفت‌وگو منبع تغییر کند، آن پنجره نمی‌تواند در منبع جایگزین ذخیره کند. تغییر هم‌زمان همان جایگاه به‌جای بازنویسی رد می‌شود.

URL نخست همچنان منبع عادی کانال است. جایگاه‌های تکراری و خالی نادیده گرفته می‌شوند. حداکثر 256 رکورد کانال و 256 KiB پیکربندی پذیرفته می‌شود. URLهای دارای اعتبارنامه در بخش اطلاعات کاربر، فاصلهٔ سفید، نویسهٔ کنترلی، بک‌اسلش یا درگاه نامعتبر رد می‌شوند. توکن‌های پارامتر پرس‌وجوی ارائه‌دهنده همچنان می‌توانند بخشی از URL رسانه باشند: تنظیمات پشتیبان پیکربندی محلی منبع هستند، نه سازوکاری برای اشتراک‌گذاری یا عمومی‌کردن اعتبارنامه‌ها.

پشتیبان‌ها **فقط برای پخش زنده** هستند. درخواست‌های آرشیو و VOD هرگز از جایگزین زنده استفاده نمی‌کنند، زیرا ضبط، مبدأ زمان، حقوق دسترسی و معنای جابه‌جایی در زمان ممکن است متفاوت باشد. مالک باید نقاط پایانی زندهٔ هم‌ارز و مجاز ارائه کند. یکسان‌بودن عنوان کانال، هم‌ارزی را اثبات نمی‌کند. با تغییر نقطهٔ پایانی انتقال، هویت ذخیره‌شدهٔ کانال، علاقه‌مندی‌ها و اتصال EPG بدون تغییر می‌مانند.

## تضمین‌های بازیابی

- هر درخواست در مجموع حداکثر **دو تلاش مجدد با تأخیر برای خطای گذرا روی همان URL** و حداکثر یک حرکت رو به جلو به هر یک از سه جایگاه پشتیبان دارد: پس از شروع اولیه، حداکثر پنج بار بازایجاد. این سهمیه با نمونهٔ جدید رمزگشا یا مانیفست موفق بازنشانی نمی‌شود. بازیابی محدود شبکه و رمزگشایی درون موتور HLS که از قبل وجود دارد، پیش از این سیاست بازیابی بیرونی اجرا می‌شود.
- خطاهای تجزیهٔ مانیفست/سطح HLS برای هر درخواست حداکثر یک اتصال مجدد به همان URL را مجاز می‌کنند که جزو همان مجموع دو تلاش است. رمزگشای جدید یا نقطهٔ پایانی پشتیبان این حد را بازنشانی نمی‌کند.
- خطاهای شبکه بدون وضعیت، HTTP 408/429 و 5xx می‌توانند از سهمیهٔ خطاهای گذرا استفاده کنند. سایر HTTP 4xx می‌توانند به جایگزین تنظیم‌شده منتقل شوند، اما همان URL را دوباره امتحان نمی‌کنند. HTTP **401/403 و خطاهای ورود به منبع درخواست را خاتمه می‌دهند**، بدون امتحان‌کردن اعتبارنامه‌های دیگر یا نقاط پایانی پشتیبان.
- خطاهای رمزگشایی می‌توانند به پشتیبان صریح بعدی بروند. محدودیت کیفیت غیرقابل‌تحقق موجب خاتمه می‌شود. چرخه‌ای برای بازگشت به منبع اصلی وجود ندارد.
- تأخیر ابتدا 500 میلی‌ثانیه، سپس 1 ثانیه، 1.5 ثانیه و پس از آن حداکثر 2 ثانیه است. فراخوانی‌های بازگشتی تکراری ادغام می‌شوند.
- مکث، زمان‌سنج برنامه‌ریزی‌شده را حذف می‌کند ولی تلاش مجدد معلق را نگه می‌دارد؛ ادامه آن را دوباره زمان‌بندی می‌کند. توقف، آماده‌به‌کار، جایگزینی منبع و جایگزینی کانال فراخوانی‌های با تأخیر را بی‌اعتبار می‌کنند. درخواستِ دچار شکست نهایی به انتخاب دوبارهٔ صریح نیاز دارد و رمزگشای کنارگذاشته‌شده‌اش خودکار پخش نمی‌شود.
- خطاهای بارگذاری Shaka و رویدادهای خطای بحرانی همین مسیر را طی می‌کنند؛ خطاهای لغو نادیده گرفته می‌شوند. اتصال مجدد منتظر پایان آزادسازی ناهم‌زمان Shaka می‌ماند.
- بازیابی، ارجاع غیرشفاف Stalker را دوباره حل می‌کند و دسترسی به منبع محافظت‌شده را دوباره آماده می‌کند. URL لوپ‌بک منقضی‌شدهٔ iOS را مجدداً به کار نمی‌برد. موقعیت VOD/آرشیو پیش از آزادسازی نمونه‌برداری می‌شود؛ پشتیبان‌های زنده از لبهٔ زندهٔ خود شروع می‌شوند.

این سیاست یک نگهبان دوم برای فریم متوقف‌شده اضافه نمی‌کند. بازیابی‌های موجود کیوسک، خودکار/بومی و HLS همچنان خطاهای مشاهده‌شدهٔ مربوط به خود را پوشش می‌دهند. جریانی که بی‌صدا متوقف می‌شود و هیچ آشکارساز موجودی خطا گزارش نمی‌کند، به عیب‌یابی جداگانه نیاز دارد.

## اعتبارسنجی و مشاهده‌پذیری

`window.__ottStreamPolicy.snapshot()` نام موتور، محدودیت‌های درخواست‌شده، قابلیت/دردسترس‌بودن، تعداد تلاش‌ها، شاخص نقطهٔ پایانی و وضعیت بازیابی را نشان می‌دهد. URL جریان یا اعتبارنامهٔ ارائه‌دهنده را در بر ندارد. شاخص صفر به معنی منبع عادی است؛ شاخص‌های بعدی به جایگزین‌های یکتا و غیرخالی اشاره دارند. این وضعیت تشخیصی است، نه API پایدار کنترل از راه دور.

اجرا کنید:

<div dir="ltr">

```sh
node tests/test_stream_policy.cjs
node tests/test_port_engine_lifecycle.cjs
node tests/test_settings_parity.cjs
node tests/test_media_backend.cjs
npm run test:localization
npm run typecheck
npm run build:server
node scripts/check-es5.cjs --server-only
```

</div>

آزمون‌ها فیلتر کیفیت با ترتیب غیریکنواخت گونه‌ها، فرادادهٔ ناموجود، ویرایش محدود به منبع، تعارض جایگاه، خطاهای تکراری، سهمیه‌های محدود، خطاهای مجوز HTTP، لغو با مکث/توقف/منبع، آزادسازی Shaka و حفظ موقعیت VOD را بررسی می‌کنند. پنج برچسب جدید پخش در همهٔ 88 بستهٔ زبانی توزیع‌شده ترجمه شده‌اند؛ برابری خودکار، بازبینی گویشور بومی نیست. پخش روی TV/D1 واقعی و مانیفست‌های خاص ارائه‌دهندگان همچنان به اعتبارسنجی روی دستگاه نیاز دارند.
