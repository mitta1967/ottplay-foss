Цей посібник описує реалізацію в ревізії коду цієї сторінки, а не можливості старого встановленого випуску. Програвач, служба керування/CLI та нативний застосунок Android — окремі артефакти. Оновлення одного не оновлює решту.

![Відповідальність компонентів і межі довіри](diagrams/roadmap-components.svg)

Див. [виміряний обсяг у байтах і порівняльний графік](roadmap-size.uk.md); швидкість виконання та відтворення на пристроях потребують окремих приймальних перевірок.

<a id="what-is-implemented"></a>

## Що реалізовано

1. **Відомий аудіовізуальний зразок.** [Інформація → Звук](audio-video-check.uk.md) відтворює восьмисекундний ролик із here.now (потрібен інтернет), з лівими/правими тонами та відповідними спалахами. Завантаження відбувається лише після **Відтворити**, ніколи під час запуску; медіафайл не входить до пакетів програвача. Він тимчасово займає головний HTML5-декодер лише під час простою або перегляду прямого ефіру. Історія перегляду не записується. [Специфікація зразка](../diagnostics/README.md).
2. **Відновлюване налаштування Local/Home.** CLI керування може планувати, застосовувати, продовжувати та перевіряти профіль. Перед повтором запису з невизначеним результатом він порівнює збережені налаштування. [Процес керування](https://github.com/open-ott-play/ottplay-control-server/blob/9b28c08eefca3948c78336e7e16a45e6fc492e31/docs/reliable-control.md).
3. **Обмежене відновлення відтворення.** Тимчасові помилки HLS/Shaka використовують спільну скінченну політику відновлення. Помилки автентифікації та непідтримуваний DRM остаточно завершують запит. Stop, зміна каналу та заміна джерела скасовують застарілі операції.
4. **Збережені обмеження якості.** Максимальні висота та бітрейт обмежують адаптивний вибір; перехід на нативний рушій не повинен непомітно обходити активну межу.
5. **Налаштування доріжок нативного Android.** Незалежний застосунок Android запам'ятовує намір за мовою/роллю/підписом, включно з Auto та вимкненими субтитрами, замість перенесення індексу доріжки з іншого потоку.
6. **Оператори команд з обмеженими правами.** Контролер може дозволити обліковим даним конкретні пристрої/дії, не передаючи адміністративних облікових даних.
7. **Явні прив'язки XMLTV.** Канал у межах списку відтворення можна прив'язати до конкретного джерела та XMLTV ID. [Прив'язки програми й доступність](guide-binding-accessibility.uk.md).
8. **Фільми та серіали Xtream.** Медіатека ліниво завантажує вибраний каталог, а потім епізоди серіалу. [Контракт медіатеки](xtream-media.uk.md).
9. **Доступні класичні елементи керування.** Списки каналів повідомляють семантику вибору; модальні діалоги утримують і відновлюють клавіатурний фокус; повідомлення мають живу область.
10. **Стійкі результати команд.** Необов'язковий обмежений журнал контролера зберігає метадані дедуплікації та результатів. Перезапуск ніколи не повторює команди наосліп.
11. **Явне передавання пристрою.** Посилання на ефір/архів передаються програвачу з тим самим налаштованим джерелом. Одержувач сам визначає власний URL. [Контракт](remote-handoff.uk.md).
12. **Явні резервні потоки.** Канали прямого ефіру можуть використовувати налаштовані альтернативи в межах тієї самої скінченної політики відновлення. [Обмеження, відновлення та резерви](playback-stream-policy.uk.md).
13. **Відновлювані пакети налаштувань.** Нативний localStorage використовує журнал відкочування для підтримуваних записів кількох ключів. [Гарантії зберігання](settings-recovery.uk.md).

<a id="language-and-compatibility-coverage"></a>

## Мови та сумісність

Програвач містить 88 каталогів перекладів. Сім нових підписів якості/медіа перекладено в кожному каталозі; інші нові меню використовують наявні перекладені рядки. Перевірки каталогів охоплюють відповідність ключів, параметри підстановки та перевірені винятки. Парні інженерні посібники пояснюють ті самі обмеження реалізації [24 мовами документації](manual-translations.md). [Локалізовані початкові сторінки](readme/README.md) — короткі інструкції запуску, а не твердження, що кожен історичний інженерний документ має 88 повних перекладів.

Класичний результат складання зберігає синтаксис ES5. Це не означає, що кожен пристрій підтримує всі кодеки, Web API, гарантії зберігання чи нативні інтеграції. A/V-перегляд обмежений головним керованим шляхом HTML5; рушії пристроїв, які його замінюють, зокрема PC2/Video.js і нативні, виключено. Явні прив'язки програми використовують хостовану або нативну реалізацію XMLTV; необов'язкові зовнішні протоколи companion можуть їх не підтримувати. Приймання для конкретного пристрою й далі потребує самого пристрою.

<a id="reproduce-the-checks"></a>

## Відтворення перевірок

```sh
npm ci
npm run typecheck
npm run test:localization
npm test
npm run build:server
npm run check:es5
npm run check:size
python3 scripts/check-av-diagnostic.py diagnostics/av-v1.mp4
```

Медіаверифікатор потребує FFmpeg/FFprobe. Він декодує обидва аудіоканали й перевіряє їхню енергію, розділення та тишу; сама наявність доріжки AAC не доводить наявності чутного вмісту. Звичайні тести JavaScript перевіряють скасування, невдалі записи, відновлення після перезапуску, зміни джерела й некоректні вхідні дані. Фінальні перевірки пакета охоплюють необов'язкові сімейства провайдерів, а не лише головний вхідний файл.

У контролері виконайте `go test -race ./...`, `go vet ./...` і `python3 -m unittest discover -s tests`. У нативному Android запустіть модульні тести налаштувань доріжок і резервних копій налаштувань та зберіть debug APK. CI кожного репозиторію підтверджує відповідний коміт, а не змінене пізніше дерево.

<a id="physical-acceptance-before-promotion"></a>

## Фізичне приймання перед просуванням випуску

- На цільовому телевізорі виконайте A/V-перевірку й підтвердьте лівий/правий звук, видимі спалахи, Stop і повернення до прямого ефіру. Тести декодера не доводять звук HDMI чи плавність.
- Перевірте дозволені/відхилені потоки, несправний резерв і зміну каналу під час очікування повтору. Підтвердьте вибране обмеження якості на фактичному рушії.
- Перевірте фокус списків/діалогів клавіатурою, пультом і доступним читачем екрана.
- Прив'яжіть дві схожі назви каналів до різних XMLTV ID та перевірте програму.
- Перервіть застосування тестового профілю, перезапустіть контролер, продовжте й перевірте. Передайте перегляд джерелам як із відповідною, так і з невідповідною конфігурацією.
- У нативному Android перемкніться між потоками з різним порядком доріжок, перезапустіть застосунок і підтвердьте явні Auto/Off та бажану мову.

Успішне надсилання, збережені налаштування, декодовані зразки та пройдені модульні тести — різні докази. Просування випуску має зберігати це розрізнення; див. [стратегію випусків](../RELEASING.md).
