เครื่องเล่น HTML5/HLS/Shaka ที่ระบบจัดการจะรักษาสิทธิ์การเล่นหนึ่งชุดไว้ระหว่างกู้คืนจากแหล่งที่ล้มเหลว และสามารถใช้ URL สำรองที่กำหนดไว้อย่างชัดเจนได้สูงสุดสามรายการต่อช่องสด เครื่องเล่นจะไม่ค้นหา คาดเดา หรือแทนที่ช่องจากชื่อช่องเด็ดขาด

<a id="set-a-quality-ceiling"></a>

## กำหนดเพดานคุณภาพ

เปิด **การตั้งค่า → การตั้งค่าอินเทอร์เฟซ** แล้วกำหนด **ความสูงวิดีโอสูงสุด (HLS/Shaka)** และ/หรือ **บิตเรตสตรีมสูงสุด (HLS/Shaka)** ข้อจำกัดทั้งสองมีผลร่วมกัน **อัตโนมัติ** จะยกเลิกข้อจำกัดนั้น ตัวเลือกที่รองรับคือ 360/480/720/1080/2160 พิกเซล และ 1/2/4/8/16 Mbps การตั้งค่าจะบันทึกในเครื่อง ใช้กระบวนการบันทึก/ยกเลิกการตั้งค่าตามปกติ และมีผลเมื่อเริ่มเล่นครั้งถัดไป รวมถึงการเริ่มใหม่เพื่อกู้คืน

นี่คือเพดาน ไม่ใช่การตั้งค่าแปลงรหัส สตรีมที่มีเฉพาะ 1080p ไม่สามารถกลายเป็น 720p ได้ หากไม่มีรูปแบบที่ประกาศไว้ตรงตามข้อจำกัด เครื่องเล่นจะแสดง **No stream meets the quality limits** และหยุดลองคำขอนั้นซ้ำ ความสูงหรือบิตเรตที่ไม่ทราบค่าไม่สามารถยืนยันได้ว่ารูปแบบ HLS ตรงตามข้อจำกัด

การกรองรูปแบบ HLS เกิดขึ้นก่อนโหลดชิ้นส่วนสตรีม hls.js รุ่นปัจจุบันจะนำรูปแบบที่ไม่ผ่านเกณฑ์ออก ส่วนรุ่นเก่าที่ไม่มี `removeLevel` จะเก็บได้เฉพาะช่วงต้นที่ต่อเนื่องและปลอดภัย จึงอาจปฏิเสธแมนิเฟสต์ที่มีรูปแบบเหมาะสมอยู่ภายหลัง Shaka ใช้ข้อจำกัด `maxHeight`/`maxBandwidth` ของแอปพลิเคชัน การปรับอัตโนมัติยังคงทำงานระหว่างรูปแบบที่เหลือ

การตั้งค่าเหล่านี้ใช้กับเอนจิน HLS และ Shaka ที่ระบบจัดการ HTML5 ธรรมดา ตัวถอดรหัสเนทีฟของแพลตฟอร์ม และเอนจิน TV/STB เดิมที่ยังเก็บไว้ไม่ได้เปิดให้ควบคุมแบบเดียวกัน โหมดอัตโนมัติอาจเลือกเล่นแบบเนทีฟ การตั้งค่านี้ไม่ได้บังคับให้ใช้ MSE เครื่องเล่นจะไม่เปลี่ยนคำขอ HLS ที่มีข้อจำกัดอยู่แล้วไปเป็นการเล่นเนทีฟไร้ข้อจำกัดเพียงเพื่อหลบข้อผิดพลาดการถอดรหัส และไม่ได้หมายความว่ามีตัวแปลงรหัสเนทีฟ การทดสอบประสิทธิภาพฮาร์ดแวร์อัตโนมัติ หรือการรับรองว่าเอาต์พุตจริงเป็น 720p

<a id="configure-explicit-backups"></a>

## กำหนดแหล่งสำรองอย่างชัดเจน

1. เริ่มช่องสดที่ต้องการ
2. เปิด **ข้อมูล → สตรีมสำรอง**
3. เลือกช่องเก็บ 1, 2 หรือ 3 แล้วป้อน URL สื่อ HTTP/HTTPS ที่สมบูรณ์
4. เปิดช่องเก็บที่ใช้อยู่ซ้ำเพื่อ **แก้ไข** หรือ **ลบ** เริ่มช่องทีวีใหม่เพื่อใช้รายการที่อัปเดต

แต่ละช่องเก็บเป็นของเนมสเปซพื้นที่จัดเก็บของผู้ให้บริการปัจจุบัน และคู่ `sourceId`/`channelId` ที่ตรงกันทุกประการ รุ่นการเล่นปัจจุบันกับการกำหนดค่าแหล่งจะจำกัดขอบเขตที่ตัวแก้ไขใช้ได้ หากเปลี่ยนแหล่งขณะที่กล่องโต้ตอบเปิดอยู่ กล่องนั้นจะไม่สามารถบันทึกลงในแหล่งที่มาแทนได้ การเปลี่ยนแปลงช่องเก็บเดียวกันพร้อมกันจะถูกปฏิเสธแทนการเขียนทับ

URL แรกยังคงเป็นแหล่งปกติของช่อง โดยข้ามช่องเก็บที่ซ้ำหรือว่าง ยอมรับข้อมูลสูงสุด 256 ช่องและการกำหนดค่าขนาด 256 KiB URL ที่มีข้อมูลรับรองในส่วนข้อมูลผู้ใช้ ช่องว่าง อักขระควบคุม แบ็กสแลช หรือพอร์ตไม่ถูกต้องจะถูกปฏิเสธ โทเค็นคิวรีจากผู้ให้บริการยังอาจเป็นส่วนหนึ่งของ URL สื่อได้ การตั้งค่าแหล่งสำรองเป็นการกำหนดค่าแหล่งในเครื่อง ไม่ใช่กลไกแบ่งปันหรือเปิดเผยข้อมูลรับรองต่อสาธารณะ

แหล่งสำรองใช้กับ **สตรีมสดเท่านั้น** คำขอรายการย้อนหลังและ VOD ไม่ใช้แหล่งสดแทน เพราะการบันทึก จุดเริ่มต้นเวลา สิทธิ์ และความหมายของการเลื่อนไปยังตำแหน่งเวลาอาจต่างกัน เจ้าของต้องระบุปลายทางสดที่เทียบเท่ากันและได้รับอนุญาต ชื่อช่องที่ตรงกันไม่ใช่หลักฐานว่าเทียบเท่ากัน ตัวตนช่องที่บันทึกไว้ รายการโปรด และการผูก EPG จะไม่เปลี่ยนเมื่อปลายทางการรับส่งเปลี่ยน

<a id="recovery-guarantees"></a>

## สิ่งที่การกู้คืนรับประกัน

- คำขอมี **การลอง URL เดิมซ้ำแบบหน่วงเวลาสำหรับข้อผิดพลาดชั่วคราวรวมไม่เกินสองครั้ง** และเลื่อนไปข้างหน้าได้ไม่เกินหนึ่งครั้งต่อช่องสำรองแต่ละช่องในสามช่อง จึงสร้างการเล่นใหม่ได้ไม่เกินห้าครั้งหลังเริ่มครั้งแรก โควตานี้ไม่เริ่มนับใหม่เมื่อมีตัวถอดรหัสอินสแตนซ์ใหม่หรือได้แมนิเฟสต์สำเร็จ การกู้คืนเครือข่ายและการถอดรหัส HLS แบบจำกัดภายในเอนจินที่มีอยู่จะทำงานก่อนนโยบายกู้คืนภายนอกนี้
- ความล้มเหลวในการแยกวิเคราะห์แมนิเฟสต์/ระดับ HLS อนุญาตให้เชื่อมต่อ URL เดิมใหม่ไม่เกินหนึ่งครั้งต่อคำขอ โดยนับรวมอยู่ในโควตาสองครั้งเดียวกัน ตัวถอดรหัสใหม่หรือปลายทางสำรองไม่ทำให้ขีดจำกัดนี้เริ่มนับใหม่
- ความล้มเหลวเครือข่ายที่ไม่มีสถานะ, HTTP 408/429 และ 5xx ใช้โควตาข้อผิดพลาดชั่วคราวได้ HTTP 4xx อื่นอาจเปลี่ยนไปยังทางเลือกที่กำหนดไว้ แต่ไม่ลอง URL เดิมซ้ำ HTTP **401/403 และข้อผิดพลาดการลงชื่อเข้าใช้แหล่งจะยุติคำขอ** โดยไม่ทดลองข้อมูลรับรองอื่นหรือปลายทางสำรอง
- ความล้มเหลวการถอดรหัสอาจเลื่อนไปยังแหล่งสำรองที่กำหนดไว้อย่างชัดเจน ขีดจำกัดคุณภาพที่เป็นไปไม่ได้จะยุติคำขอ ไม่มีการวนกลับไปยังแหล่งหลัก
- ระยะหน่วงคือ 500 ms, 1 s, 1.5 s แล้วไม่เกิน 2 s คอลแบ็กที่ซ้ำจะถูกรวมกัน
- การพักจะนำตัวจับเวลาที่กำหนดไว้ออกแต่เก็บการลองซ้ำที่รออยู่ไว้ การเล่นต่อจะกำหนดเวลาใหม่ การหยุด สแตนด์บาย การเปลี่ยนแหล่ง และการเปลี่ยนช่องจะทำให้คอลแบ็กที่หน่วงไว้ใช้ไม่ได้ คำขอที่ล้มเหลวขั้นสุดท้ายต้องให้ผู้ใช้เลือกใหม่อย่างชัดเจน แทนการเล่นตัวถอดรหัสที่เลิกใช้แล้วโดยอัตโนมัติ
- ความล้มเหลวในการโหลด Shaka และเหตุการณ์ข้อผิดพลาดร้ายแรงใช้เส้นทางเดียวกัน ส่วนข้อผิดพลาดจากการยกเลิกจะถูกละเว้น การแนบใหม่จะรอให้การทำลาย Shaka แบบอะซิงโครนัสเสร็จสิ้น
- การกู้คืนจะแก้การอ้างอิง Stalker แบบทึบใหม่ และเตรียมการเข้าถึงแหล่งที่ได้รับการปกป้องอีกครั้ง โดยไม่ใช้ URL ลูปแบ็ก iOS ที่หมดอายุซ้ำ ตำแหน่ง VOD/รายการย้อนหลังจะถูกอ่านไว้ก่อนรื้อถอน ส่วนแหล่งสำรองสดจะเริ่มที่ขอบสดของตน

นโยบายนี้ไม่ได้เพิ่มตัวเฝ้าระวังเฟรมค้างตัวที่สอง การกู้คืนคีออสก์ อัตโนมัติ/เนทีฟ และ HLS ที่มีอยู่ยังคงดูแลกรณีล้มเหลวที่ตนตรวจพบ สตรีมที่หยุดนิ่งเงียบ ๆ โดยไม่มีตัวตรวจจับเดิมรายงานข้อผิดพลาดต้องได้รับการวินิจฉัยแยกต่างหาก

<a id="verification-and-observability"></a>

## การตรวจสอบและการสังเกตสถานะ

`window.__ottStreamPolicy.snapshot()` เปิดเผยชื่อเอนจิน ขีดจำกัดที่ร้องขอ ความสามารถ/ความพร้อมใช้งาน จำนวนครั้งที่ลองซ้ำ ดัชนีปลายทาง และสถานะกู้คืน โดยไม่มี URL สตรีมหรือข้อมูลรับรองของผู้ให้บริการ ดัชนีศูนย์หมายถึงแหล่งปกติ ดัชนีถัดไปอ้างถึงทางเลือกที่ไม่ว่างและไม่ซ้ำ นี่คือสถานะสำหรับวินิจฉัย ไม่ใช่ API ควบคุมระยะไกลที่รับรองความคงที่

เรียกใช้:

```sh
node tests/test_stream_policy.cjs
node tests/test_port_engine_lifecycle.cjs
node tests/test_settings_parity.cjs
node tests/test_media_backend.cjs
npm run test:localization
npm run typecheck
npm run build:server
node scripts/check-es5.cjs --server-only
```

การทดสอบครอบคลุมการกรองคุณภาพเมื่อรูปแบบไม่ได้เรียงตามลำดับเพิ่มหรือลด เมทาดาทาที่ไม่มี การแก้ไขภายในขอบเขตแหล่ง ความขัดแย้งของช่องเก็บ ข้อผิดพลาดซ้ำ โควตาที่จำกัด ความล้มเหลวการอนุญาต HTTP การยกเลิกด้วยพัก/หยุด/แหล่ง การรื้อถอน Shaka และการรักษาตำแหน่ง VOD ป้ายข้อความการเล่นใหม่ห้ารายการได้รับการแปลในชุดภาษาที่จัดส่งทั้ง 88 ชุด การตรวจความตรงกันอัตโนมัติไม่ใช่การตรวจโดยเจ้าของภาษา การเล่นบน TV/D1 จริงและแมนิเฟสต์เฉพาะผู้ให้บริการยังต้องตรวจสอบบนอุปกรณ์ [ซอร์สไดอะแกรมที่แก้ไขได้](diagrams/stream-recovery.mmd)
