![Порівняння всього JavaScript програвача однаковими інструментами](diagrams/roadmap-size.svg)

Ця сторінка зберігає вимірювання JavaScript для наведених нижче знімків вихідного коду. Вони не вимірюють поточну ревізію, інсталяційні пакети чи мережевий трафік.

У початковому порівнянні головна точка входу разом з усіма необов’язковими сімействами провайдерів зросла на **31 128 байтів без стиснення / 9 759 байтів gzip**: приблизно **3.23% / 3.20%**. Це збільшення вартості функцій, а не заявлене зменшення розміру чи прискорення виконання. Xtream і далі завантажується на вимогу; винесення з точки входу не прибирає його із загальної суми.

Вимірювання порівнює чисті архіви коду `bbf9ca7b` і `cae971da`, обидва версії 1.1.55, з Node 26.8.2, TypeScript 5.9.3, Terser 5.51.2 та zlib 1.2.12. Воно використовує виробничий складальник ES5, оптимізатор, правила іменування та правильну ідентичність чистого коду. Gzip рівня 9 застосовується окремо до кожного створеного ресурсу.

- Вебточка входу: 848 092 / 262 392 → 874 926 / 270 321 байтів без стиснення/gzip.
- Вебточка входу + всі провайдери: 964 459 / 305 344 → 995 587 / 315 103.
- Нативна точка входу: 848 050 / 262 460 → 874 884 / 270 372.
- Нативна точка входу + всі провайдери: 964 417 / 305 412 → 995 545 / 315 154.
- Необов’язковий M3U зростає на 184 байти без стиснення / 82 байти gzip; новий Xtream займає 4 110 / 1 748. Інші шість необов’язкових сімейств побайтово однакові.

До перенесення ролика на here.now заміна його URL локальним шляхом від кореня додала один байт JavaScript без стиснення в цій історичній послідовності. Це не вимірювання пізнішого розміщеного URL. Виправлення обмежених повторних спроб розбору HLS додає 37 байтів без стиснення / 36 байтів gzip в ізольованому порівнянні одного знімка ([підтвердження](evidence/parse-recovery-size-20261015.json)). Виправлення володіння нативним передаванням Auto додає ще 101 байт без стиснення / 39 байтів gzip ([підтвердження](evidence/auto-recovery-size-20261015.json)). Підсумок без стиснення до виправлень регресій доступності — 995 726 байтів; ідентичність збірки та кількість байтів gzip можуть змінитися у фінальному коміті. Остаточний `build/reports/classic-bundle.json` та `npm run check:size` залишаються визначальними для точної поставленої ревізії. Наступна чиста збірка `652726f8` з виправленнями фокусу вказівника й діалогів дає **995 858 байтів без стиснення / 315 207 байтів gzip** для повного вебпрогравача ([підтвердження фінального артефакту](evidence/roadmap-final-size-20261015.json)). Її точка входу — 875 197 / 270 425; нативні підсумки — 995 816 / 315 259. Ліміти цього знімка зберегли попередній запас для нативного середовища/Node/суфікса релізу: 875 300 без стиснення / 271 600 gzip для точки входу; 996 100 / 316 400 для точки входу з провайдерами.

## Інтеграція після бети

![Повний JavaScript після інтеграції beta.4](diagrams/post-beta-size.svg)

Пізніше порівняння відтворює код beta.4 `39287792` щодо runtime `9663b681`, включно з інтеграцією Plex і відновленням пошкоджених налаштувань, із тими самими Node 26.8.2, Rollup 4.64.5 та Terser 5.51.2:

- Вебточка входу: 848 315 / 262 443 → 879 533 / 271 761 байтів без стиснення/gzip.
- Вебточка входу + всі провайдери: 964 876 / 305 452 → 1 000 388 / 316 600.
- Нативна точка входу + всі провайдери: 964 834 / 305 520 → 1 000 346 / 316 654.
- Зростання повного вебкоду: **35 512 / 11 148 байтів (3.68% / 3.65%)**.

Базова версія враховує сім сімейств провайдерів, інтегрована — вісім, зокрема Xtream із завантаженням на вимогу. Ліміти точки входу цього знімка становили 879 900 / 273 000; загальні — 1 000 800 / 317 800, із запасом для нативного середовища, Node та ідентичності релізу. Обидві локальні виробничі збірки заново створюють п’ять відстежуваних runtime-файлів і не заявляють ревізію чистого коду. Це локально відтворені артефакти, а не опубліковані бінарні файли бети. Версії інструментів, хеші й це обмеження записані в [базових даних](evidence/post-beta-baseline-size-20261015.json) та [даних інтеграції](evidence/post-beta-candidate-size-20261015.json). [Звіт про реалізацію](implementation-report.uk.md#post-beta-integration-and-review) пояснює виправлення й перевірку.

**Охоплення:** ці суми JavaScript не включають зовнішні медіарушії, мовні словники, CSS, зображення й відео. Історичні пакети також містили **A/V-ролик розміром 464 652 байти**, поза наведеними сумами. Його поточна доставка відокремлена від цих вимірювань:

- **Репозиторій:** `diagnostics/av-v1.mp4` залишається з генератором і перевіркою заради відтворюваності. Збереження вихідного файлу не означає включення до пакета.
- **Пакети:** Web/OTTPlay Server, Tauri, Capacitor і Docker виключають ролик. Це прибирає 464 652 байти нестиснених медіаданих, а не доводить зменшення стисненого інсталятора на 464 652 байти. Формат архіву та інші зміни збірки впливають на його розмір.
- **Мережа:** програвач отримує ролик із here.now лише коли користувач запускає [A/V-перевірку](audio-video-check.uk.md). Їй потрібен інтернет; для відтворення під час запуску ролик не завантажується.

Наведені історичні вимірювання JavaScript залишаються незмінними. Щоб виміряти вплив розміщеного URL на JavaScript чи поточний інсталятор, потрібне нове порівняння. 88 локалізованих README — документація репозиторію, а не код, що постачається програвачу. Це порівняння байтів не підтверджує тверджень про час запуску, частоту кадрів, пам’ять чи продуктивність великих каталогів. Для цього потрібні окремі вимірювання на цільових пристроях.
