[Володіння декодером](device-media-backend.md)

Керований HTML5/HLS/Shaka-програвач зберігає єдине право володіння відтворенням під час відновлення після відмови джерела. Для живого каналу він також може використовувати до трьох явно налаштованих резервних URL. Він ніколи не шукає, не вгадує та не підміняє канал за назвою.

![Відновлення: одне право володіння, скінченні повтори, явні резерви](diagrams/stream-recovery.svg)

<a id="set-a-quality-ceiling"></a>

## Налаштування верхньої межі якості

Відкрийте **Налаштування → Налаштування інтерфейсу** та задайте **Максимальну висоту відео (HLS/Shaka)** та/або **Максимальний бітрейт потоку (HLS/Shaka)**. Обидва обмеження діють разом. **Автоматично** знімає відповідне обмеження. Підтримуються 360/480/720/1080/2160 пікселів і 1/2/4/8/16 Mbps. Налаштування зберігаються локально, беруть участь у звичайному збереженні/скасуванні й набувають чинності при наступному запуску відтворення, включно з перезапуском для відновлення.

Це верхні межі, а не параметри перекодування. Потік лише 1080p не стане 720p. Якщо жоден оголошений варіант не підходить, програвач повідомляє **No stream meets the quality limits** і припиняє повтори запиту. Невідомі висота/бітрейт не доводять відповідність обмеженого варіанта HLS.

Варіанти HLS фільтруються до завантаження фрагментів. Поточний hls.js видаляє непридатні варіанти; старі збірки без `removeLevel` можуть зберегти лише безпечний неперервний префікс і можуть відхилити маніфест із придатними варіантами далі у списку. Shaka використовує обмеження застосунку `maxHeight`/`maxBandwidth`. Автоматична адаптація триває серед решти варіантів.

Налаштування стосуються керованих рушіїв HLS і Shaka. Звичайний HTML5, нативні декодери платформ і збережені рушії TV/STB не надають тих самих засобів керування. Auto може вибрати нативне відтворення; налаштування не примушує його до MSE. Програвач не переведе вже обмежений запит HLS на необмежене нативне відтворення лише для обходу помилки декодування. Нативний транскодер, автоматичний апаратний бенчмарк або твердження про фізичний вихід 720p не маються на увазі.

<a id="configure-explicit-backups"></a>

## Налаштування явних резервів

1. Запустіть потрібний канал прямого ефіру.
2. Відкрийте **Інформація → Резервні потоки**.
3. Виберіть позицію 1, 2 або 3 і введіть повний HTTP/HTTPS URL медіа.
4. Повторно відкрийте зайняту позицію для **Редагування** або **Видалення**. Знову запустіть канал, щоб використати оновлений список.

Кожна позиція належить поточному простору зберігання провайдера й точній парі `sourceId`/`channelId`. Поточне покоління відтворення та конфігурація джерела обмежують редактор. Зміна джерела за відкритого діалогу не дозволяє цьому діалогу зберегти дані в нове джерело. Одночасна зміна тієї самої позиції відхиляється, а не перезаписується.

Перший URL залишається звичайним джерелом каналу. Дубльовані та порожні позиції пропускаються. Приймаються максимум 256 записів каналів і 256 KiB конфігурації. URL з обліковими даними в user-info, пробільними або керівними символами, зворотними скісними рисками чи некоректним портом відхиляються. Токени провайдера в параметрах запиту все ще можуть входити до URL медіа: резервні налаштування — локальна конфігурація джерела, а не механізм поширення чи публікації облікових даних.

Резерви працюють **лише в прямому ефірі**. Архівні й VOD-запити ніколи не використовують живу альтернативу: запис, початок відліку часу, права та семантика перемотування можуть відрізнятися. Власник має надати еквівалентні дозволені живі адреси. Збіг назви каналу не доводить еквівалентності. Збережені ідентичність каналу, обране та прив'язка EPG не змінюються при заміні транспортної адреси.

<a id="recovery-guarantees"></a>

## Гарантії відновлення

- Запит має максимум **дві відкладені тимчасові повторні спроби того самого URL загалом** і по одному переходу вперед до кожного з трьох резервів: щонайбільше п'ять повторних створень після першого запуску. Новий екземпляр декодера чи успішний маніфест не скидають бюджет. Наявне обмежене відновлення мережі та декодування всередині HLS працює до цієї зовнішньої політики.
- Помилки розбору маніфесту/рівня HLS допускають максимум одне перепідключення до того самого URL на запит у межах того самого ліміту двох повторів. Новий декодер чи резервна адреса не скидають обмеження.
- Мережеві помилки без статусу, HTTP 408/429 і 5xx можуть використовувати тимчасовий бюджет. Інші HTTP 4xx можуть перейти до налаштованої альтернативи, але не повторюють той самий URL. **HTTP 401/403 і помилки входу до джерела завершують запит**, без випробування альтернативних облікових даних або резервних адрес.
- Помилки декодування можуть переходити вперед до явного резерву. Нездійсненні обмеження якості завершують запит. Циклічного повернення до головного джерела немає.
- Затримка становить 500 ms, 1 s, 1.5 s, потім максимум 2 s. Повторні зворотні виклики об'єднуються.
- Pause прибирає запланований таймер, зберігаючи очікуваний повтор; Resume планує його знову. Stop, режим очікування, заміна джерела та каналу роблять відкладені виклики недійсними. Після остаточної відмови потрібен явний повторний вибір, а не автоматичний запуск виведеного з роботи декодера.
- Помилки завантаження Shaka й критичні події помилок використовують цей самий шлях; помилки скасування ігноруються. Повторне приєднання очікує асинхронного знищення Shaka.
- Відновлення заново розв'язує непрозоре посилання Stalker і готує захищений доступ до джерела. Прострочений iOS loopback URL не використовується повторно. Позиція VOD/архіву фіксується до демонтажу; живі резерви стартують зі своєї поточної точки ефіру.

Політика не додає другого спостерігача за завмерлими кадрами. Наявне відновлення kiosk, Auto/native і HLS надалі покриває власні спостережувані відмови. Потік, який мовчки завис без повідомлення помилки від будь-якого наявного детектора, потребує окремої діагностики.

<a id="verification-and-observability"></a>

## Перевірка та спостережуваність

`window.__ottStreamPolicy.snapshot()` показує назву рушія, запитані обмеження, можливості/доступність, кількість повторів, індекс адреси та стан відновлення. Він не містить URL потоку чи облікових даних провайдера. Індекс нуль означає звичайне джерело; наступні — непорожні унікальні альтернативи. Це діагностичний стан, а не стабільний API дистанційного керування.

Виконайте:

```sh
node tests/test_stream_policy.cjs
node tests/test_port_engine_lifecycle.cjs
node tests/test_settings_parity.cjs
node tests/test_media_backend.cjs
npm run test:localization
npm run typecheck
npm run build:server
node scripts/check-es5.cjs --server-only
```

Тести перевіряють фільтрацію якості за немонотонного порядку варіантів, недоступні метадані, редагування в межах джерела, конфлікти позицій, повторні помилки, обмежені бюджети, помилки HTTP-авторизації, скасування паузою/зупинкою/джерелом, демонтаж Shaka та збереження позиції VOD. П'ять нових підписів відтворення перекладено в усіх 88 мовних пакетах; автоматична відповідність не є перевіркою носієм мови. Фізичне відтворення TV/D1 і маніфести конкретних провайдерів усе ще потребують перевірки на пристрої. [Редаговане джерело діаграми](diagrams/stream-recovery.mmd).
