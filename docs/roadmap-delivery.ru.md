Эта инструкция описывает реализацию в ревизии исходников этой страницы, а не возможности старого установленного релиза. Плеер, сервер управления с CLI и отдельное Android-приложение — разные артефакты. Обновление одного не обновляет остальные.

![Ответственность компонентов и границы доверия](diagrams/roadmap-components.svg)

См. [измеренный объём в байтах и график сравнения](roadmap-size.ru.md); скорость выполнения и воспроизведение на устройствах проверяются отдельно.

<a id="what-is-implemented"></a>

## Что реализовано

1. **Известный аудиовидеоролик.** [Информация → Звук](audio-video-check.ru.md) воспроизводит восьмисекундный ролик с here.now (нужен интернет) с левыми/правыми тонами и соответствующими вспышками. Он загружается только после **Воспроизвести**, никогда при старте; медиафайл не входит в пакеты плеера. Он временно занимает основной HTML5-декодер только при простое или просмотре прямого эфира. История просмотра не записывается. [Спецификация ролика](../diagnostics/README.md).
2. **Возобновляемая настройка Local/Home.** CLI управления умеет планировать, применять, продолжать и проверять профиль. Перед повтором записи с неопределённым исходом он сравнивает сохранённые настройки. [Процесс управления](https://github.com/open-ott-play/ottplay-control-server/blob/9b28c08eefca3948c78336e7e16a45e6fc492e31/docs/reliable-control.md).
3. **Ограниченное восстановление воспроизведения.** Временные ошибки HLS/Shaka используют общую конечную политику восстановления. Ошибки аутентификации и неподдерживаемый DRM завершают запрос. Stop, смена канала и замена источника отменяют устаревшие операции.
4. **Сохраняемые ограничения качества.** Максимальные высота и битрейт ограничивают адаптивный выбор; переход на нативный движок не должен незаметно обходить действующее ограничение.
5. **Предпочтения дорожек нативного Android.** Отдельное Android-приложение запоминает намерение по языку/роли/подписи, включая Auto и выключенные субтитры, вместо переноса индекса дорожки из другого потока.
6. **Операторы команд с ограниченными правами.** Контроллер может выдать учётным данным доступ к конкретным устройствам/действиям без передачи административных учётных данных.
7. **Явные привязки XMLTV.** Канал в области плейлиста можно связать с конкретным источником и XMLTV ID. [Привязки программы и доступность](guide-binding-accessibility.ru.md).
8. **Фильмы и сериалы Xtream.** Медиатека лениво загружает выбранный каталог, затем эпизоды сериала. [Контракт медиатеки](xtream-media.ru.md).
9. **Доступные классические элементы управления.** Списки каналов сообщают семантику выбора; модальные диалоги удерживают и возвращают клавиатурный фокус; уведомления имеют live region.
10. **Устойчивые результаты команд.** Необязательный ограниченный журнал контроллера сохраняет сведения о дедупликации и исходах. Перезапуск никогда не повторяет команды вслепую.
11. **Явная передача просмотра устройству.** Ссылки на эфир/архив передаются плееру с тем же настроенным источником. Получатель сам разрешает свой URL. [Контракт](remote-handoff.ru.md).
12. **Явные резервные потоки.** Каналы прямого эфира используют настроенные альтернативы в рамках той же конечной политики восстановления. [Ограничения, восстановление и резервы](playback-stream-policy.ru.md).
13. **Восстанавливаемые пакеты настроек.** Нативный localStorage использует журнал отката для поддерживаемых записей нескольких ключей. [Гарантии хранения](settings-recovery.ru.md).

<a id="language-and-compatibility-coverage"></a>

## Языки и совместимость

Плеер поставляется с 88 каталогами переводов. Семь новых подписей качества/медиа переведены в каждом каталоге; другие новые меню используют уже переведённые строки. Проверки каталогов охватывают соответствие ключей, параметры подстановки и согласованные исключения. Парные инженерные инструкции объясняют те же ограничения реализации на [24 языках документации](manual-translations.md). [Локализованные входные страницы](readme/README.md) — инструкции быстрого старта, а не утверждение о 88 полных переводах каждого исторического инженерного документа.

Классическая сборка сохраняет синтаксис ES5. Это не означает, что каждое устройство поддерживает все кодеки, Web API, гарантии хранения или нативные интеграции. A/V-проверка ограничена основным управляемым HTML5-путём; подменяющие его движки устройств, например PC2/Video.js и нативные движки, исключены. Явная привязка программы использует hosted- или native-реализацию XMLTV; необязательные внешние companion-протоколы могут её не поддерживать. Приёмка для конкретного устройства по-прежнему требует самого устройства.

<a id="reproduce-the-checks"></a>

## Повторение проверок

```sh
npm ci
npm run typecheck
npm run test:localization
npm test
npm run build:server
npm run check:es5
npm run check:size
python3 scripts/check-av-diagnostic.py diagnostics/av-v1.mp4
```

Медиаверификатору нужны FFmpeg/FFprobe. Он декодирует оба аудиоканала и проверяет их энергию, разделение и тишину; наличие AAC-дорожки само по себе не доказывает наличие слышимого содержимого. Обычные JavaScript-тесты проверяют отмену, неудачные записи, восстановление после перезапуска, смену источника и некорректные входные данные. Финальные проверки сборки включают необязательные семейства провайдеров, а не только основной входной файл.

В контроллере выполните `go test -race ./...`, `go vet ./...` и `python3 -m unittest discover -s tests`. В нативном Android запустите модульные тесты предпочтений дорожек и резервирования настроек, соберите debug APK. CI каждого репозитория подтверждает соответствующий коммит, а не изменённое позднее дерево.

<a id="physical-acceptance-before-promotion"></a>

## Физическая приёмка перед продвижением релиза

- На целевом телевизоре выполните A/V-проверку, подтвердите левый/правый звук, видимые вспышки, Stop и возврат к прямому эфиру. Тесты декодера не доказывают звук HDMI или плавность.
- Проверьте разрешённые/запрещённые потоки, отказ резерва и смену канала во время ожидающего повтора. Подтвердите выбранное ограничение качества на фактическом движке.
- Проверьте фокус списков/диалогов клавиатурой, пультом и доступным экранным диктором.
- Привяжите два похожих названия каналов к разным XMLTV ID и проверьте программу.
- Прервите применение тестового профиля, перезапустите контроллер, продолжите и проверьте. Передайте просмотр источнику как с совпадающей, так и с несовпадающей конфигурацией.
- В нативном Android переключитесь между потоками с разным порядком дорожек, перезапустите приложение и подтвердите явные Auto/Off и предпочтительный язык.

Успешная отправка команды, сохранённые настройки, декодированные образцы и пройденные модульные тесты — разные подтверждения. Продвижение релиза должно сохранять это различие; см. [стратегию выпуска](../RELEASING.md).
