![Сравнение всего JavaScript плеера одинаковым набором инструментов](diagrams/roadmap-size.svg)

Эта страница сохраняет измерения JavaScript для указанных ниже снимков исходного кода. Они не измеряют текущую ревизию, установочные пакеты или сетевой трафик.

В исходном сравнении основная точка входа вместе со всеми необязательными семействами провайдеров выросла на **31 128 байт без сжатия / 9 759 байт gzip**: примерно **3.23% / 3.20%**. Это увеличение стоимости функций, а не заявленное уменьшение размера или ускорение выполнения. Xtream по-прежнему загружается по требованию; перенос за пределы точки входа не исключает его из общей суммы.

Измерение сравнивает чистые архивы исходников `bbf9ca7b` и `cae971da`, оба версии 1.1.55, с Node 26.8.2, TypeScript 5.9.3, Terser 5.51.2 и zlib 1.2.12. Используются производственный сборщик ES5, оптимизатор, правила именования и корректный идентификатор чистых исходников. Gzip уровня 9 применяется отдельно к каждому выходному файлу.

- Веб-точка входа: 848 092 / 262 392 → 874 926 / 270 321 байт без сжатия/gzip.
- Веб-точка входа + все провайдеры: 964 459 / 305 344 → 995 587 / 315 103.
- Нативная точка входа: 848 050 / 262 460 → 874 884 / 270 372.
- Нативная точка входа + все провайдеры: 964 417 / 305 412 → 995 545 / 315 154.
- Необязательный M3U вырос на 184 байта без сжатия / 82 байта gzip; новый Xtream занимает 4 110 / 1 748. Остальные шесть необязательных семейств побайтово идентичны.

До переноса ролика на here.now замена его URL локальным путём от корня добавила один байт JavaScript без сжатия в этой исторической последовательности. Это не измерение более позднего размещённого URL. Исправление ограниченных повторных попыток разбора HLS добавляет 37 байт без сжатия / 36 байт gzip в изолированном сравнении одного снимка ([подтверждение](evidence/parse-recovery-size-20261015.json)). Исправление владения нативной передачей Auto добавляет ещё 101 байт без сжатия / 39 байт gzip ([подтверждение](evidence/auto-recovery-size-20261015.json)). Итоговый размер без сжатия до исправления регрессий доступности составляет 995 726 байт; идентификатор сборки и размер gzip могут измениться в финальном коммите. Для точной поставляемой ревизии определяющими остаются итоговый `build/reports/classic-bundle.json` и `npm run check:size`. Последующая чистая сборка `652726f8` с исправлениями фокуса указателя и диалогов даёт **995 858 байт без сжатия / 315 207 байт gzip** для полного веб-плеера ([подтверждение финального артефакта](evidence/roadmap-final-size-20261015.json)). Её точка входа занимает 875 197 / 270 425; нативные итоги — 995 816 / 315 259. Лимиты этого снимка сохранили прежний запас для нативного окружения, Node и суффикса релиза: 875 300 без сжатия / 271 600 gzip для точки входа; 996 100 / 316 400 для точки входа с провайдерами.

## Интеграция после беты

![Полный JavaScript после интеграции beta.4](diagrams/post-beta-size.svg)

Более позднее сравнение воспроизводит исходники beta.4 `39287792` относительно runtime `9663b681`, включая интеграцию Plex и восстановление повреждённых настроек, с теми же Node 26.8.2, Rollup 4.64.5 и Terser 5.51.2:

- Веб-точка входа: 848 315 / 262 443 → 879 533 / 271 761 байт без сжатия/gzip.
- Веб-точка входа + все провайдеры: 964 876 / 305 452 → 1 000 388 / 316 600.
- Нативная точка входа + все провайдеры: 964 834 / 305 520 → 1 000 346 / 316 654.
- Прирост полного веб-кода: **35 512 / 11 148 байт (3.68% / 3.65%)**.

Базовая версия учитывает семь семейств провайдеров, интегрированная — восемь, включая загружаемый по требованию Xtream. Лимиты точки входа этого снимка составляли 879 900 / 273 000; общие лимиты — 1 000 800 / 317 800 с запасом для нативного окружения, Node и идентификатора релиза. Обе локальные производственные сборки заново создают пять отслеживаемых runtime-файлов и не заявляют ревизию чистых исходников. Это локально воспроизведённые артефакты, а не опубликованные бинарные файлы беты. Версии инструментов, хеши и это ограничение зафиксированы в [данных базового измерения](evidence/post-beta-baseline-size-20261015.json) и [интеграции](evidence/post-beta-candidate-size-20261015.json). [Отчёт о реализации](implementation-report.ru.md#post-beta-integration-and-review) объясняет исправления и проверки.

**Охват:** эти суммы JavaScript не включают внешние медиадвижки, языковые словари, CSS, изображения и видео. Исторические пакеты плеера также содержали **A/V-ролик размером 464 652 байта**, не вошедший в указанные суммы. Его нынешняя доставка рассматривается отдельно от этих измерений:

- **Репозиторий:** `diagnostics/av-v1.mp4` остаётся вместе с генератором и проверкой ради воспроизводимости. Наличие исходного файла не означает его включения в пакет.
- **Пакеты:** Web/OTTPlay Server, Tauri, Capacitor и Docker исключают ролик. Это убирает 464 652 байта несжатых медиаданных, а не доказывает уменьшение сжатого установщика на 464 652 байта. На размер установщика влияют формат архива и другие изменения сборки.
- **Сеть:** плеер получает ролик с here.now только при запуске пользователем [A/V-проверки](audio-video-check.ru.md). Проверке нужен интернет; при стартовом воспроизведении ролик не загружается.

Приведённые исторические измерения JavaScript остаются неизменными. Чтобы измерить влияние размещённого URL на JavaScript или текущий установщик, нужно новое сравнение. 88 локализованных README — документация репозитория, а не поставляемый код плеера. Сравнение байтов не подтверждает заявления о времени запуска, частоте кадров, памяти или производительности больших каталогов. Для этого нужны отдельные измерения на целевых устройствах.
