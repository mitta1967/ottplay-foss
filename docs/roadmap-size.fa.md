![مقایسهٔ همهٔ JavaScript پخش‌کننده با زنجیره‌ابزار یکسان](diagrams/roadmap-size.svg)

این صفحه اندازه‌گیری‌های JavaScript از نسخه‌های لحظه‌ای منبع زیر را حفظ می‌کند. این اعداد، بازبینی فعلی، بسته‌های نصب یا ترافیک شبکه را اندازه نمی‌گیرند.

در مقایسهٔ اولیه، ورودی اصلی به‌همراه همهٔ خانواده‌های اختیاری ارائه‌دهنده **31 128 بایت خام / 9 759 بایت gzip**، حدود **3.23% / 3.20%**، رشد کرد. این افزایش هزینهٔ قابلیت‌هاست، نه ادعای بهبود اندازه یا سرعت اجرا. Xtream همچنان هنگام نیاز بارگیری می‌شود؛ خارج‌کردن آن از ورودی، آن را از مجموع حذف نمی‌کند.

اندازه‌گیری آرشیوهای منبع پاک `bbf9ca7b` و`cae971da` را که هر دو نسخهٔ 1.1.55 هستند با Node 26.8.2، TypeScript 5.9.3، Terser 5.51.2 وzlib 1.2.12 مقایسه می‌کند. از مونتاژگر ES5 تولیدی، بهینه‌ساز، سیاست نام‌گذاری و هویت صحیح منبع پاک استفاده می‌شود. gzip سطح 9 جداگانه بر هر دارایی خروجی اعمال می‌شود.

- ورودی وب: 848 092 / 262 392 → 874 926 / 270 321 بایت خام/gzip.
- ورودی وب + همهٔ ارائه‌دهندگان: 964 459 / 305 344 → 995 587 / 315 103.
- ورودی بومی: 848 050 / 262 460 → 874 884 / 270 372.
- ورودی بومی + همهٔ ارائه‌دهندگان: 964 417 / 305 412 → 995 545 / 315 154.
- M3U اختیاری 184 بایت خام / 82 gzip رشد می‌کند؛ Xtream جدید 4 110 / 1 748 است. شش خانوادهٔ اختیاری دیگر بایت‌به‌بایت یکسان‌اند.

پیش از انتقال کلیپ به here.now، تغییر URL آن به مسیر محلی از ریشه در این توالی تاریخی یک بایت خام JavaScript افزود. این اندازه‌گیری URL میزبانی‌شدهٔ بعدی نیست. اصلاح تلاش مجدد محدودِ تجزیهٔ HLS در مقایسهٔ جداگانهٔ همان نسخهٔ لحظه‌ای 37 بایت خام / 36 gzip می‌افزاید ([شاهد](evidence/parse-recovery-size-20261015.json)). اصلاح مالکیت تحویل Auto بومی 101 بایت خام / 39 gzip دیگر اضافه می‌کند ([شاهد](evidence/auto-recovery-size-20261015.json)). مجموع خام پیش از اصلاح پس‌رفت‌های دسترس‌پذیری 995 726 بایت است؛ هویت ساخت و بایت‌های gzip ممکن است در کامیت نهایی تغییر کنند. `build/reports/classic-bundle.json` نهایی و`npm run check:size` همچنان مرجع دقیق نسخهٔ تحویل‌شده‌اند. ساخت پاک بعدی `652726f8` شامل اصلاح فوکوس اشاره‌گر/گفت‌وگو، برای پخش‌کنندهٔ کامل وب **995 858 بایت خام / 315 207 gzip** اندازه دارد ([شاهد خروجی نهایی](evidence/roadmap-final-size-20261015.json)). ورودی آن 875 197 / 270 425 و مجموع بومی 995 816 / 315 259 است. سقف‌های آن نسخه حاشیهٔ قبلی بومی/Node/پسوند انتشار را حفظ کردند: 875 300 خام / 271 600 gzip برای ورودی؛ 996 100 / 316 400 برای ورودی و ارائه‌دهندگان.

## یکپارچه‌سازی پس از بتا

![JavaScript کامل پس از یکپارچه‌سازی beta.4](diagrams/post-beta-size.svg)

مقایسهٔ بعدی منبع beta.4 یعنی `39287792` را در برابر زمان‌اجرای `9663b681`، شامل یکپارچه‌سازی Plex و بازیابی تنظیمات خراب، با همان Node 26.8.2، Rollup 4.64.5 وTerser 5.51.2 بازتولید می‌کند:

- ورودی وب: 848 315 / 262 443 → 879 533 / 271 761 بایت خام/gzip.
- ورودی وب + همهٔ ارائه‌دهندگان: 964 876 / 305 452 → 1 000 388 / 316 600.
- ورودی بومی + همهٔ ارائه‌دهندگان: 964 834 / 305 520 → 1 000 346 / 316 654.
- افزایش محتوای کامل وب: **35 512 / 11 148 بایت (3.68% / 3.65%)**.

مبنای مقایسه هفت خانوادهٔ ارائه‌دهنده و نسخهٔ یکپارچه هشت خانواده، شامل Xtream با بارگیری هنگام نیاز، را می‌شمارد. سقف ورودی آن نسخه 879 900 / 273 000 و سقف کل 1 000 800 / 317 800 بود؛ فضای بومی، Node و هویت انتشار حفظ شد. هر دو ساخت تولیدی محلی پنج فایل زمان‌اجرای تحت کنترل نسخه را دوباره تولید می‌کنند و ادعای بازبینی منبع پاک را حذف می‌کنند. این‌ها خروجی‌های بازتولیدشدهٔ محلی‌اند، نه باینری‌های بتای منتشرشده. نسخهٔ ابزارها، هش‌ها و این محدودیت در [شواهد مبنا](evidence/post-beta-baseline-size-20261015.json) و[شواهد یکپارچه‌سازی](evidence/post-beta-candidate-size-20261015.json) ثبت شده‌اند. [گزارش پیاده‌سازی](implementation-report.fa.md#post-beta-integration-and-review) اصلاح‌ها و اعتبارسنجی را توضیح می‌دهد.

**دامنه:** این مجموع‌های JavaScript موتورهای رسانهٔ خارجی، واژه‌نامه‌های زبان، CSS، تصویر و ویدیو را شامل نمی‌شوند. بسته‌های تاریخی پخش‌کننده یک **کلیپ A/V با اندازهٔ 464 652 بایت** نیز داشتند که خارج از مجموع‌های بالاست. تحویل فعلی آن از این اندازه‌گیری‌ها جداست:

- **مخزن:** `diagnostics/av-v1.mp4` برای بازتولیدپذیری با تولیدکننده و اعتبارسنج خود باقی می‌ماند. نگهداری فایل منبع به‌معنای گنجاندن در بسته نیست.
- **بسته‌ها:** Web/OTTPlay Server، Tauri، Capacitor وDocker کلیپ را کنار می‌گذارند. این کار 464 652 بایت خام رسانه را حذف می‌کند، نه کاهش اندازه‌گیری‌شدهٔ 464 652 بایتی در نصب‌کنندهٔ فشرده. قالب آرشیو و تغییرات دیگر ساخت بر اندازه اثر دارند.
- **شبکه:** پخش‌کننده تنها وقتی کاربر [آزمون A/V](audio-video-check.fa.md) را آغاز کند کلیپ را از here.now می‌گیرد. آزمون اینترنت می‌خواهد؛ کلیپ برای پخش هنگام راه‌اندازی دریافت نمی‌شود.

اندازه‌گیری‌های تاریخی JavaScript بالا بدون تغییر می‌مانند. سنجش اثر URL میزبانی‌شده بر JavaScript یا نصب‌کنندهٔ فعلی، مقایسهٔ تازه می‌خواهد. 88 فایل README ترجمه‌شده مستندات مخزن‌اند، نه محتوای پخش‌کننده. این مقایسهٔ بایت‌ها هیچ ادعایی دربارهٔ زمان راه‌اندازی، نرخ فریم، حافظه یا کارایی در مقیاس کاتالوگ نتیجه نمی‌دهد. این موارد به اندازه‌گیری جداگانه روی دستگاه‌های هدف نیاز دارند.
