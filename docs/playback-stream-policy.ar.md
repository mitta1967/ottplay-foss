[ملكية مفكّك الترميز](device-media-backend.md)

يحتفظ مشغّل HTML5/HLS/Shaka المُدار بحجز تشغيل واحد أثناء التعافي من مصدر متعطّل. ويمكنه أيضًا استخدام ما يصل إلى ثلاثة عناوين URL احتياطية مضبوطة صراحة لقناة مباشرة. ولا يكتشف قناة أو يخمّنها أو يستبدلها بناءً على عنوانها مطلقًا.

![مسار الاستعادة: حجز واحد، محاولات محدودة، وبدائل صريحة](diagrams/stream-recovery.svg)

<a id="set-a-quality-ceiling"></a>

## تعيين سقف للجودة

افتح **الإعدادات ← إعدادات الواجهة** واضبط **أقصى ارتفاع للفيديو (HLS/Shaka)** و/أو **أقصى معدل بت للبث (HLS/Shaka)**. يُطبّق القيدان معًا. يزيل الخيار **تلقائي** القيد المقابل. الخيارات المدعومة هي 360/480/720/1080/2160 بكسل و1/2/4/8/16 ميغابت/ثانية. تُحفظ الإعدادات محليًا، وتخضع لمسار حفظ الإعدادات أو إلغائها المعتاد، وتسري عند بدء التشغيل التالي، بما في ذلك إعادة التشغيل للاستعادة.

هذه سقوف وليست إعدادات لتحويل الترميز. البث المتاح بدقة 1080p فقط لا يمكن أن يصبح 720p. إذا لم يلائم أي متغير مُعلَن الحدود، يعرض المشغّل **No stream meets the quality limits** ويتوقف عن إعادة محاولة ذلك الطلب. الارتفاع أو معدل البت المجهول لا يثبت أن متغير HLS يفي بالقيود.

تُرشّح متغيرات HLS قبل تحميل المقاطع. يزيل hls.js الحالي المتغيرات غير المؤهلة؛ أما الإصدارات الأقدم التي تفتقر إلى `removeLevel` فلا تستطيع الاحتفاظ إلا بمقدمة متصلة آمنة، وقد ترفض بيانًا تتوافر فيه متغيرات مؤهلة لاحقًا. يستخدم Shaka قيود التطبيق `maxHeight`/`maxBandwidth`. ويستمر التكيف التلقائي بين المتغيرات المتبقية.

تنطبق هذه الإعدادات على محركَي HLS وShaka المُدارَين. لا توفّر HTML5 العادية ولا مفكّكات الترميز الأصلية للمنصة ولا محركات TV/STB المحتفظ بها عناصر التحكم نفسها. قد يختار الوضع التلقائي التشغيل الأصلي؛ ولا يفرض عليه هذا الإعداد استخدام MSE. لن يحوّل المشغّل طلب HLS مُقيّدًا بالفعل إلى تشغيل أصلي غير مقيّد لمجرد تجنّب خطأ فك الترميز. ولا يعني ذلك وجود محوّل ترميز أصلي أو اختبار أداء تلقائي للعتاد أو ادعاء إخراج فعلي بدقة 720p.

<a id="configure-explicit-backups"></a>

## ضبط بدائل صريحة

1. شغّل القناة المباشرة المطلوبة.
2. افتح **المعلومات ← التدفقات الاحتياطية**.
3. اختر الخانة 1 أو 2 أو 3 وأدخل عنوان URL كاملًا لوسائط عبر HTTP/HTTPS.
4. أعد فتح خانة مشغولة لاختيار **تعديل** أو **حذف**. شغّل القناة من جديد لاستخدام القائمة المحدّثة.

تنتمي كل خانة إلى نطاق أسماء تخزين المزوّد الحالي وإلى الزوج المحدّد `sourceId`/`channelId`. يحدّد جيل التشغيل الحالي وإعداد المصدر نطاق صلاحية المحرّر. يمنع تبديل المصادر أثناء فتح مربع حوار ذلك المربع من الحفظ في المصدر البديل. ويُرفض التغيير المتزامن للخانة نفسها بدلًا من الكتابة فوقه.

يبقى عنوان URL الأول هو المصدر المعتاد للقناة. تُتجاوز الخانات المكرّرة والفارغة. يُقبل حد أقصى قدره 256 سجل قناة و256 KiB من الإعدادات. تُرفض عناوين URL التي تحتوي على بيانات اعتماد ضمن معلومات المستخدم أو فراغات أو محارف تحكم أو شرطات مائلة عكسية أو منفذ غير صالح. قد تبقى رموز الاستعلام التي يقدّمها المزوّد جزءًا من عنوان URL للوسائط: إعدادات البدائل هي إعدادات مصدر محلية، وليست آلية لمشاركة بيانات الاعتماد أو نشرها.

البدائل مخصّصة **للبث المباشر فقط**. لا تستخدم طلبات الأرشيف وVOD بديلًا مباشرًا مطلقًا، إذ قد يختلف التسجيل ونقطة الأصل الزمنية والحقوق ودلالات الانتقال داخل المحتوى. على المالك توفير نقاط نهاية مباشرة مكافئة ومصرّح بها. تطابق عنوان القناة ليس دليلًا على التكافؤ. وتبقى هوية القناة المحفوظة والمفضّلة وربط EPG دون تغيير عند تغيّر نقطة نهاية نقلها.

<a id="recovery-guarantees"></a>

## ضمانات الاستعادة

- لا يتجاوز الطلب **محاولتين مؤجلتين إجمالًا لإعادة المحاولة المؤقتة على عنوان URL نفسه**، مع انتقال أمامي واحد على الأكثر إلى كل خانة من الخانات الاحتياطية الثلاث: أي خمس عمليات إعادة إنشاء على الأكثر بعد البدء الأولي. لا يُصفَّر هذا الحد بإنشاء مفكّك ترميز جديد أو بنجاح تحميل بيان. تُنفّذ استعادة الشبكة وفك الترميز المحدودة الموجودة داخل محرك HLS قبل سياسة الاستعادة الخارجية هذه.
- تسمح أخطاء تحليل بيان/مستوى HLS بإعادة اتصال واحدة على الأكثر بعنوان URL نفسه لكل طلب، محسوبة ضمن إجمالي المحاولتين ذاته. ولا يُصفِّر مفكّك ترميز جديد أو نقطة نهاية احتياطية هذا الحد.
- يمكن لأعطال الشبكة بلا حالة وHTTP 408/429 و5xx استخدام رصيد المحاولات المؤقتة. ويمكن لأخطاء HTTP 4xx الأخرى الانتقال إلى بديل مضبوط، لكنها لا تعيد محاولة عنوان URL نفسه. أما HTTP **401/403 وأخطاء تسجيل الدخول إلى المصدر فتنهي الطلب**، دون اختبار بيانات اعتماد بديلة أو نقاط نهاية احتياطية.
- قد تتقدم أخطاء فك الترميز إلى بديل صريح. أما حدود الجودة المستحيلة فتنهي الطلب. ولا توجد دورة تعود إلى المصدر الأساسي.
- التأخير هو 500 مللي ثانية، ثم 1 ثانية، ثم 1.5 ثانية، ثم 2 ثانية على الأكثر. تُدمج الاستدعاءات الراجعة المتكررة.
- يزيل الإيقاف المؤقت المؤقّت المجدول مع الاحتفاظ بالمحاولة المعلّقة؛ وتعيد المتابعة جدولته. يُبطل الإيقاف ووضع الاستعداد واستبدال المصدر واستبدال القناة الاستدعاءات المؤجّلة. ويتطلب الطلب المنتهي بالفشل إعادة اختيار صريحة بدلًا من التشغيل التلقائي لمفكّك الترميز الذي أُخرج من الخدمة.
- تستخدم أخطاء تحميل Shaka وأحداث الخطأ الحرجة المسار نفسه؛ وتُتجاهل أخطاء الإلغاء. ينتظر إعادةُ الإرفاق اكتمالَ إتلاف Shaka غير المتزامن.
- تعيد الاستعادة حلّ مرجع Stalker المعتم وتجهّز الوصول إلى المصدر المحمي من جديد. ولا تعيد استخدام عنوان URL حلقي محلي منتهي الصلاحية على iOS. يُلتقط موضع VOD/الأرشيف قبل التفكيك؛ وتبدأ البدائل المباشرة عند الطرف الحي للبث.

لا تضيف هذه السياسة مراقبًا ثانيًا للإطارات المتوقفة. تظل استعادة وضع الكشك والوضع التلقائي/الأصلي وHLS القائمة مسؤولة عن حالات الفشل التي ترصدها كل منها. والبث الذي يتوقف بصمت دون أن يبلغ أي كاشف موجود عن خطأ يحتاج إلى تشخيص منفصل.

<a id="verification-and-observability"></a>

## التحقق وقابلية الرصد

يعرض `window.__ottStreamPolicy.snapshot()` اسم المحرك والحدود المطلوبة والإمكانات/التوافر وعدد المحاولات وفهرس نقطة النهاية وحالة الاستعادة. ولا يحتوي على عنوان URL للبث أو بيانات اعتماد المزوّد. يعني الفهرس صفر المصدر المعتاد؛ وتشير الفهارس اللاحقة إلى بدائل فريدة غير فارغة. هذه حالة تشخيصية وليست واجهة API مستقرة للتحكم عن بُعد.

شغّل:

<div dir="ltr">

```sh
node tests/test_stream_policy.cjs
node tests/test_port_engine_lifecycle.cjs
node tests/test_settings_parity.cjs
node tests/test_media_backend.cjs
npm run test:localization
npm run typecheck
npm run build:server
node scripts/check-es5.cjs --server-only
```

</div>

تختبر الاختبارات ترشيح الجودة عندما لا يكون ترتيب المتغيرات رتيبًا، وغياب البيانات الوصفية، والتحرير ضمن نطاق المصدر، وتعارض الخانات، والأخطاء المكرّرة، والحدود المنتهية للمحاولات، وأخطاء تفويض HTTP، وإلغاء الإيقاف المؤقت/الإيقاف/المصدر، وتفكيك Shaka، والاحتفاظ بموضع VOD. تُرجمت تسميات التشغيل الخمس الجديدة في جميع حزم اللغات الـ88 المشحونة؛ والتحقق الآلي من التكافؤ ليس مراجعة من ناطق أصلي. لا يزال التشغيل على TV/D1 فعلي وبيانات المزوّد الخاصة يتطلب تحققًا على الجهاز.
