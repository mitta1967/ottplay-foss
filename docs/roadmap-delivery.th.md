ดู[ขนาดไบต์ที่วัดได้และกราฟเปรียบเทียบ](roadmap-size.th.md) ความเร็วในการทำงานและการเล่นบนอุปกรณ์เป็นการตรวจรับคนละส่วน

<a id="what-is-implemented"></a>

## สิ่งที่พัฒนาแล้ว

1. **ตัวอย่างเสียง/วิดีโอที่ทราบเนื้อหาแน่นอน** [ข้อมูล → เสียง](audio-video-check.th.md) เล่นคลิปแปดวินาทีจาก here.now (ต้องใช้อินเทอร์เน็ต) พร้อมเสียงซ้าย/ขวาและแสงกะพริบที่ตรงกัน ดึงข้อมูลหลังเลือก **เล่น** เท่านั้น ไม่ดึงตอนเริ่มต้น ไฟล์สื่อไม่รวมในแพ็กเกจตัวเล่น ยืมตัวถอดรหัส HTML5 หลักชั่วคราวเฉพาะขณะว่างหรือดูทีวีสด และไม่เขียนประวัติการรับชม [ข้อกำหนดตัวอย่าง](../diagnostics/README.md)
2. **การตั้งค่า Local/Home ที่ทำต่อได้** CLI ควบคุมวางแผน ใช้ ทำต่อ และตรวจสอบค่าที่ตั้งไว้ล่วงหน้าได้ โดยเปรียบเทียบค่าที่บันทึกก่อนลองเขียนซ้ำเมื่อผลครั้งก่อนยังไม่แน่ชัด [ขั้นตอนการควบคุม](https://github.com/open-ott-play/ottplay-control-server/blob/9b28c08eefca3948c78336e7e16a45e6fc492e31/docs/reliable-control.md)
3. **การกู้การเล่นที่มีขีดจำกัด** ความล้มเหลวชั่วคราวของ HLS/Shaka ใช้นโยบายกู้คืนที่มีขอบเขตร่วมกัน ข้อผิดพลาดยืนยันตัวตนและ DRM ที่ไม่รองรับจะยุติคำขอ Stop การเปลี่ยนช่อง และการแทนที่แหล่งข้อมูลจะยกเลิกงานที่ล้าสมัย
4. **ขีดจำกัดคุณภาพที่บันทึกไว้** ความสูงและบิตเรตสูงสุดจำกัดการเลือกแบบปรับตัว การเปลี่ยนไปเล่นแบบเนทีฟต้องไม่ข้ามเพดานที่ใช้งานอยู่โดยเงียบ ๆ
5. **ค่าที่ต้องการสำหรับแทร็กบน Android เนทีฟ** แอป Android แยกต่างหากจดจำเจตนาตามภาษา/บทบาท/ป้ายกำกับ รวม Auto และปิดคำบรรยาย แทนการนำดัชนีแทร็กจากสตรีมอื่นมาใช้
6. **ผู้ใช้คำสั่งที่จำกัดขอบเขต** ตัวควบคุมให้ข้อมูลรับรองมีสิทธิ์เฉพาะอุปกรณ์/การกระทำที่กำหนดได้ โดยไม่ให้ข้อมูลรับรองผู้ดูแล
7. **การผูก XMLTV อย่างชัดเจน** ช่องภายในขอบเขตเพลย์ลิสต์ผูกกับฟีดและ ID XMLTV ที่เจาะจงได้ [การผูกผังรายการและการเข้าถึง](guide-binding-accessibility.th.md)
8. **ภาพยนตร์และซีรีส์ Xtream** คลังสื่อดึงแค็ตตาล็อกที่เลือกเมื่อจำเป็น แล้วจึงดึงตอนของซีรีส์ [สัญญาการทำงานของคลัง](xtream-media.th.md)
9. **การควบคุมคลาสสิกที่เข้าถึงได้** รายการช่องสื่อความหมายของการเลือก กล่องโต้ตอบโมดัลเก็บและคืนโฟกัสแป้นพิมพ์ การแจ้งเตือนมีบริเวณแจ้งข้อมูลสด
10. **ผลคำสั่งที่คงทน** สมุดบันทึกตัวควบคุมแบบมีขีดจำกัดที่เปิดใช้ได้ตามต้องการเก็บเมทาดาทาป้องกันคำสั่งซ้ำและผลลัพธ์ การเริ่มใหม่ไม่เล่นคำสั่งซ้ำอย่างไร้การตรวจสอบ
11. **การส่งต่ออุปกรณ์อย่างชัดเจน** การอ้างอิงสด/ย้อนหลังส่งไปยังตัวเล่นที่ตั้งค่าแหล่งข้อมูลเดียวกัน ปลายทางแปลงเป็น URL ของตนเอง [สัญญาการทำงาน](remote-handoff.th.md)
12. **สตรีมสำรองที่ระบุชัดเจน** ช่องสดใช้ตัวเลือกสำรองที่ตั้งค่าไว้ภายในนโยบายกู้คืนแบบมีขีดจำกัดเดียวกันได้ [ขีดจำกัด การกู้คืน และสตรีมสำรอง](playback-stream-policy.th.md)
13. **ชุดการตั้งค่าที่กู้คืนได้** localStorage เนทีฟใช้บันทึกย้อนกลับสำหรับการเขียนหลายคีย์ที่รองรับ [การรับประกันการจัดเก็บ](settings-recovery.th.md)

## ขอบเขตภาษาและความเข้ากันได้

ตัวเล่นมีแค็ตตาล็อกคำแปล 88 ภาษา ป้ายกำกับคุณภาพ/สื่อใหม่เจ็ดรายการได้รับการแปลในทุกแค็ตตาล็อก เมนูใหม่อื่นใช้ป้ายกำกับที่แปลไว้แล้ว การตรวจแค็ตตาล็อกครอบคลุมความตรงกันของคีย์ ตัวแทนค่า และข้อยกเว้นที่ทบทวนแล้ว คู่มือวิศวกรรมที่เป็นคู่กันอธิบายขีดจำกัดการทำงานเดียวกันใน[ภาษาเอกสาร 24 ภาษา](manual-translations.md) [หน้าทางเข้าที่แปลแล้ว](readme/README.md) เป็นคู่มือเริ่มต้นฉบับย่อ ไม่ใช่คำกล่าวว่าเอกสารวิศวกรรมในอดีตทุกฉบับมีคำแปลเต็ม 88 ภาษา

ผลลัพธ์คลาสสิกยังคงใช้ไวยากรณ์ ES5 ไม่ได้หมายความว่าทุกอุปกรณ์รองรับทุก codec, Web API, การรับประกันการจัดเก็บ หรือการเชื่อมต่อเนทีฟ ตัวอย่าง A/V จำกัดอยู่ที่เส้นทาง HTML5 หลักที่จัดการให้ ไม่รวมเอนจินอุปกรณ์ที่แทนที่ เช่น PC2/Video.js และเอนจินเนทีฟ การผูกผังรายการอย่างชัดเจนใช้ XMLTV แบบโฮสต์หรือเนทีฟ โปรโตคอล companion ภายนอกที่เป็นทางเลือกอาจไม่รองรับ การตรวจรับเฉพาะอุปกรณ์ยังต้องใช้อุปกรณ์จริง

<a id="reproduce-the-checks"></a>

## ทำการตรวจสอบซ้ำ

```sh
npm ci
npm run typecheck
npm run test:localization
npm test
npm run build:server
npm run check:es5
npm run check:size
python3 scripts/check-av-diagnostic.py diagnostics/av-v1.mp4
```

ตัวตรวจสื่อต้องใช้ FFmpeg/FFprobe โดยถอดรหัสเสียงทั้งสองช่องและตรวจพลังงาน การแยกช่อง และความเงียบ การมีแทร็ก AAC อย่างเดียวไม่ได้พิสูจน์ว่ามีเนื้อหาที่ได้ยิน การทดสอบ JavaScript ตามปกติครอบคลุมการยกเลิก การเขียนล้มเหลว การกู้คืนหลังเริ่มใหม่ การเปลี่ยนแหล่งข้อมูล และอินพุตไม่ถูกต้อง การตรวจบันเดิลขั้นสุดท้ายรวมกลุ่มผู้ให้บริการที่เป็นทางเลือก ไม่ใช่เฉพาะจุดเข้าหลัก

ในตัวควบคุมให้เรียก `go test -race ./...`, `go vet ./...` และ `python3 -m unittest discover -s tests` ใน Android เนทีฟให้ทดสอบหน่วยของค่าที่ต้องการสำหรับแทร็กและการสำรองการตั้งค่า แล้วประกอบ APK แบบดีบัก CI ของแต่ละรีโพซิทอรีรับรอง commit ที่ตรงกัน ไม่ใช่ต้นไม้ไฟล์ที่แก้ไขภายหลัง

<a id="physical-acceptance-before-promotion"></a>

## การตรวจรับบนอุปกรณ์จริงก่อนเลื่อนขั้นรุ่น

- บนทีวีเป้าหมายให้ตรวจ A/V และยืนยันเสียงซ้าย/ขวา แสงกะพริบที่เห็น Stop และการกลับสู่ทีวีสด การทดสอบตัวถอดรหัสไม่พิสูจน์เสียง HDMI หรือความลื่นไหล
- ทดลองสตรีมที่อนุญาต/ปฏิเสธ ตัวสำรองที่ล้มเหลว และการเปลี่ยนช่องระหว่างรอลองใหม่ ยืนยันขีดจำกัดคุณภาพที่เลือกบนแบ็กเอนด์จริง
- ทดสอบโฟกัสรายการ/กล่องโต้ตอบด้วยแป้นพิมพ์ รีโมต และโปรแกรมอ่านหน้าจอที่มี
- ผูกชื่อช่องคล้ายกันสองช่องกับ ID XMLTV คนละตัว แล้วตรวจข้อมูลรายการ
- ขัดจังหวะการใช้ค่าที่ตั้งไว้สำหรับทดสอบ เริ่มตัวควบคุมใหม่ ทำต่อและตรวจสอบ ส่งต่อไปยังแหล่งข้อมูลที่ตั้งค่าตรงกันและไม่ตรงกัน
- บน Android เนทีฟให้เปลี่ยนสตรีมที่มีลำดับแทร็กต่างกัน เริ่มแอปใหม่ และยืนยันพฤติกรรม Auto/Off ที่ระบุชัดกับภาษาที่ต้องการ

การส่งสำเร็จ การตั้งค่าที่บันทึก ตัวอย่างที่ถอดรหัส และการทดสอบหน่วยที่ผ่าน เป็นหลักฐานคนละประเภท การเลื่อนขั้นรุ่นต้องคงความแตกต่างนี้ไว้ ดู[กลยุทธ์การออกรุ่น](../RELEASING.md)
